# 跨交易所做市：交易所 / Tardis 迁移与市场数据规格核查

Tardis FAQ 对 Bybit 的深度汇总与频道列表存在不一致，实际可用于何种深度的回测须以指定样本日和实际 `incremental_book_L2` 内容为准，不能直接把原生 `orderBook_200` 的名称当作全历史有效200档保证。

另：Tardis `book_ticker` 是原生最优价流，`quotes` 是从 L2 重建的最优价。对跨所 lead-lag，二者更新节奏可能显著不同；主 Binance 信号宜保留原生 BBO 和 L2 各自时序。

## 4. 满足 hftbacktest 的最小数据清单

1. 目标所 L2 快照+增量，明确是原生 delta 还是快照推导的增量；价格档/数量/更新编号完整。
2. 目标所逐笔成交（价格、数量、主动买卖方向、交易时间或 ID）。交易所如以批量事件推送，也要逐条展开、保留原消息次序。
3. 目标市场与 Binance 信号的采集**本地接收时间**（同一采集服务器的单调时钟+UTC时钟同步）、原始交易所时间和两路消息原始顺序。
4. Binance 原生 BBO（`bookTicker`）或目标研究需要的订单流；不可仅用慢速L2推导 BBO 代替后就宣称毫秒级领先。
5. 目标合约当期 tick size、contract multiplier、lot size、历史上市状态和费率/返佣。
6. 记录 WS 断线、重订阅、快照恢复、序列号跳变、队列数据无效区间；禁止静默填平数据缺口。
7. 用多档 L2 模拟 HBT 队列属于 **Market-By-Price**（按价位聚合），看不到每个真实订单优先级；概率队列模型仍是需要做敏感性分析的假设。历史市场不会被我们模拟订单的市场冲击改变。

> Tardis 官方特别强调：不同采集地区的 `local_timestamp` 不适合直接进行亚毫秒级比较；多个 WS 频道之间无原生严格全局顺序。Tardis 每日00:00 UTC重连采集可能产生约0.3–3秒小缺口，应检查各日期开头与重连日志。

## 5. 可选采集方案与相对价值

| 方案 | 实施 | 优点 | 成本/风险 | 对论文适用 |
|---|---|---|---|---|
| A：全部 Tardis 免费月首日 | 五所各月1日原始历史，按真实共同覆盖日期对比；将 OKX 迁移区间作为分组 | 最长历史、最低维护开销；2020以来多市场 | Gate/Bitget 的历史深度不足，Tardis 采集跨地区时间差可能污染毫秒级领先结论；样本约每月1天 | **做主要长期历史稳健性分析** |
| B：Tardis + 自采 Binance BBO、目标所 L2/trades | 从现在起自采5所7币；优先 Gate 20ms、Bitget v3 50档20ms、Bybit 50档20ms、OKX books100ms（无高VIP时） | 新样本统一采集时钟，得到比历史更高细度的目标簿；适合延迟/队列检验 | 自采历史从启动日起积累，断线/完整性和云存储需要监控 | **推荐的混合研究方案** |
| C：仅自采 Binance + Gate | 限定1个目标所与若干币种，日常连续采集 | 复杂性最低、可检验现有6日结论是否对新日期成立 | 跨所横截面不足，未来扩所需补采 | **论文时间紧或资源紧时首选** |
| D：全自采5所7币 | 全量原始深度、成交、BBO；压缩分片归档 | 最统一的采集环境，适合比较低延迟以及各交易所深度 | 35个组合，数据吞吐/存储和升级适配负担高；2026新接口版本变化需处理 | 第二阶段，在小规模稳定后扩大 |

采用 B/C 都应**同步自采 Binance 信号与目标市场行情**。只自采目标所、仍用 Tardis 的 Binance 本地时间戳，不能消除跨采集环境差异。

### 论文后续的判断标准

- **样本可用性**：已校验 L2 初始快照、更新连续性和逐笔成交一致性；数据异常按日期/时段剔除而非假装有效。
- **精细度**：L2 原生增量/快照属性、推送间隔、深度是否覆盖策略实际报价档位和最大队列范围。
- **执行可信度**：HBT 队列模型、1/2.5/5/10/25ms 延迟敏感性、固定消息节流、手续费及合约规格一致。
- **时间可比性**：迁移前后分期；同一采集环境；跨频道时间排序保守处理。
- **经济指标**：手续费后按日独立净收益、100/500ms 成交后 Markout、库存暴露、订单次数，并单独报告数据采集质量。
