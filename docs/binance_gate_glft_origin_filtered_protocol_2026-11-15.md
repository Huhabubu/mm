# Binance 主导的跨交易所价差过滤：Gate BTC/USDT 永续 GLFT 实验协议

制定日期：2026-11-15；状态：**执行前固定协议**（当前六个日期均已被研究探索使用，结果为探索性，非严格样本外）。
目标：对照无跨所信号的 GLFT，检验 Binance 价格主动推动的异常价差是否能改善 Gate 被动做市的**手续费后每日净收益**与成交后逆向选择。

## 1. 固定实验条件

- 交易标的：Gate USDT 永续 `BTC_USDT`；跨所信号来自 Binance USDⓈ-M Futures `BTCUSDT`。
- 历史日期：2026-06-01、07-01、08-01、09-01、10-01、11-01（UTC）。每个日期独立，不允许跨日带入库存或估计值。
- 数据：Tardis 各免费月首日原始 `trades`、`incremental_book_L2`、`quotes`（Gate），Binance 原生 `book_ticker`。目标所成交撮合必须使用官方 `hftbacktest==2.4.4`，队列概率模型与延迟一致。
- 先在每日期 UTC 00:00–00:10 预热、00:10–01:00 连续回测 **50 分钟**以检查工程行为，再扩展为同日起 **00:10–24:00 共 1,430 分钟**的整日回放。只跑了 50 分钟不能报告“日收益”。
- Binance 数据可见时间：Tardis `local_timestamp` + 假设 2.5ms 额外延迟（同微秒保守偏移）。目标所按 HBT 实际可见市场盘口对齐。所有特征只依赖当前决策时刻前已经到达的事件。
- 订单提交延迟 1ms、回应延迟 1ms；同一侧两次订单动作最小间隔 20ms；不额外强制等待 20ms。使用 Gate 自身合约 tick 取整与 Post-Only 挂单。
- 沿用此前多市场实验：单边单笔挂单名义目标 **80 USDT**（每天预热期价格及 Gate 合约数量步长取整），库存绝对上限 **20 倍单笔订单量**，财富风险厌恶 **50 USDT⁻¹**；两者对所有 β 和报价模式固定，不进行盈利调参。
- GLFT 的成交强度参数 `A`、距离敏感度 `k`、价格波动率按现有 10min/100ms 环形样本、每 5s 更新；其库存模型、报价差、基本下单数量不随 β 改变。
- Gate `order_price_round`、`quanto_multiplier`、`order_size_min`、`maker_fee_rate`、`taker_fee_rate` 等由 Gate 合约公开 API 读取并保存实际观察时间与值；对照历史合约的价格档与成交数量逐日核查。账户等级/历史费率可能不同，报告标注“公开费率情景”，禁止不含费用的收益 headline。资金费率与期末平仓的额外成本如不能模拟须明确披露。
- 撤除 `B_t` 历史估计的 250ms 报价年龄截断，但事前做数据连续性与质量检查；最后已知报价持续到本所下一次更新，异常断链须在数据 QA 标记并停止/剔除相应日期，不能悄悄当作正常稳定报价。

## 2. 历史基准、标准差和跨所异常价差

设 `S_t^B` 为可见 Binance 中间价、`S_t^M` 为可见 Gate 中间价（两者单位 USDT/BTC），`D_t=S_t^B-S_t^M`。
`B_t` 是过去 600s 的**连续时间加权价差均值**，`σ_t` 为同一窗口、同一时间权重的价差总体标准差，单位 USDT/BTC：

```math
B_t=\frac{1}{600}\int_{t-600}^{t}D_u\,du,\quad
\sigma_t=\sqrt{\frac{1}{600}\int_{t-600}^{t}(D_u-B_t)^2\,du}.
```

每 5 秒在固定时钟更新 `B_t` 和 `σ_t`，精确按事件持续时间积分；每次取整个过去 600 秒窗口，且不使用未来行情；两所价格变动事件仍逐事件处理。此 `σ_t` 为跨所价差波动，**不同于 GLFT 自身波动率**。`G_t=D_t-B_t` 是异常跨所价差。

历史窗口刚开始尚无完整数据时禁止放行信号；`σ_t<=0`、数据不连续或任意价格无效时信号回退 0，并记录原因。

## 3. “正常起跑价格”锁定状态机

- 在 `|G_t| ≤ σ_t` 正常带内，每次最新行情可见时刷新 `base_B = S_t^B` 与 `base_M = S_t^M`，状态为 `READY`。
- 首次出现 `|G_t| > σ_t` 时，锁定前一条已确认正常状态的起跑价格，不再更新。直到 `|G_t| ≤ σ_t` 才重新解锁并刷新。锁定状态中 `B_t` 和 `σ_t` 继续每 5s 更新，不冻结基准。
- 若数据由预热直接越过正常带、且尚无有效起跑价格，先不放行；一旦记录到正常带才允许新一轮触发。
- 只有 `|G_t| > 1.96 σ_t` 时进入第二关。计算 `ΔS^B=S_t^B-base_B` 与 `ΔS^M=S_t^M-base_M`，要求 `sign(ΔS^B)=sign(G_t)` 且 `|ΔS^B|>|ΔS^M|`。
- 为进一步区分 Binance 主动变动与 Gate 自身变化，信号**首次放行必须由可见 Binance 的中间价实际变动事件触发**；若只有 Gate 价格变化、数量更新或同微秒先后不可确定，则不得认作新一波 Binance 主导信号。已激活的信号也要在 Gate / Binance 后续事件或滚动 5s 时钟重新检查双重条件，不满足立即归零。
- 若 `|G_t|≤σ_t`，不仅清空有效信号，还更新起跑基准、重置激活状态。BBO 的买卖量变化不应伪装成主所中间价变化。
- `G_t^{eff}=G_t` 当且仅当 1.96σ 门槛、同向/更远、有效起跑价格、Binance 价格事件激活约束均满足；其余时刻 `G_t^{eff}=0`，回退原 GLFT 价格。

注：上述是**操作性的 Binance 主导事件筛选**，不声称已经因果识别真正领先。未来价格只用于事后结果标签。

## 4. 报价模式与 β 梯度

`β∈{0,0.25,0.50,0.75,1.00}`；`β=0` 是同一套原始 GLFT，对双边模式与单边模式共享。因此每个日期 **9 个独立模型**（1 基准 + 双边 4 + 单边 4），六日 54 组/回测阶段。

设 `P_t^b`、`P_t^a` 是原始 GLFT 买价与卖价，`B_t^{best}`、`A_t^{best}` 是 Gate 最优买卖价，`δ_{tick}` 是 Gate 最小价格档位（单位 USDT/BTC）。

**双边同步平移**：
```math
P_t^{b,new}=\min(P_t^b+\beta G_t^{eff},A_t^{best}-\delta_{tick}),\quad
P_t^{a,new}=\max(P_t^a+\beta G_t^{eff},B_t^{best}+\delta_{tick}).
```

**单边防御**：
- `G_t^{eff}>0`：原始买价不变，仅 `P_t^{a,new}=P_t^a+βG_t^{eff}`（卖单远离市场）。
- `G_t^{eff}<0`：原始卖价不变，仅 `P_t^{b,new}=P_t^b+βG_t^{eff}`（买单远离市场）。
- `G_t^{eff}=0`：两侧均原始 GLFT。

**重要数学修正**：只使用对手最优盘口的 Post-Only 边界，不能自动证明新买价一定 `≤ 本所买一` 或新卖价一定 `≥ 本所卖一`；允许在价差内改善报价，但不得跨过对手最优价。还需检验两侧自有订单不交叉、取整方式及交易所 Post-Only 语义。

新价格按照 Gate 价格档位取整；仅当目标价格档位与**当前在途订单价格**实际不同且通过限频/ACK检查，才撤掉旧单后重新提交。价格未改变则保留原有排队位置。不新增局部极大值、旧 P90/P50 信号过滤或其他参数调优。

## 5. 强制数据 QA 闸门：先审计再运行

每日期至少检查：
1. Gate `trades` / `incremental_book_L2` / `quotes` 和 Binance `book_ticker` 下载成功，字段、数值、起止时间、UTC 全日覆盖完整；读入数据行顺序不倒退，记录同时间戳批次。
2. Gate 初始双侧 L2 快照存在，后续增量有效；盘口买一价低于卖一价、价格/数量有效，L2 更新价档与目标订单 tick 一致；Trade 成交数量换算为正确 Gate 合约张数（不能误把 BTC 数量当合约数量）。
3. 逐流连续时间长间隔/异常静默和可能的数据缺失：输出分布、最长间隔、阈值下的异常段；能比对时用快照或 `quotes` 重建检查深度一致性。成交 ID 的跳号不能单独证实丢失，需依平台语义判定。
4. 严格检查 `local_timestamp - timestamp` 的负延迟（HBT 可能独立平移目标所时钟），发现无法保证一致的可见时钟即失败关闭；对于已确认的普通更新频率不设置随意的 250ms 行情截断。
5. 合约规格及 maker / taker 手续费取值写入每日期 QA JSON，不能使用未经验证的 OKX/Bitget 费用替代 Gate。
6. **任何关键 QA 未通过，不启动该日期回测，不把失败日期净收益填 0。** 只有全部六日通过全日 QA 后才推进全日 54 组；50min 工程验证须先通过并保存 9模型×日期报告。

## 6. 回测记录与验证

- 每模型输出：GLFT 实时 `A,k` 等校准成功率、`B_t,σ_t,G_t` 时间线、正常/冻结/放行状态、事件来源、`βG_t^{eff}`、整数 Tick 报价目标、在途订单、实际撤单请求/确认、实盘类延迟模型、挂单/成交数量及手续费。
- 成交使用官方 HBT 的 L2 队列概率模型、延迟与成交路径；不得用中间价触发简化成交器。
- 通过单位测试和时间顺序测试：相同时间事件保守处理、严格过去 600s、5s 更新时点、一次更新跨越 1σ 和 1.96σ、基准锁定与解锁、基差更新但基准价格不随之重置、Gate 独自先动不得首次激活、仅 Binance 数量更新不得激活、平仓时的尾部和库存上限、β0 不改变 GLFT、Post-Only 不交叉以及 20ms 单侧动作限制。
- 成交后的 100ms 和 500ms 方向性中间价变化（markout，衡量买入后下跌／卖出后上涨）按官方成交被策略本地看到后的时间算，严格过去 `as-of` 提取未来期限已到达报价；不将未来价格用作当时策略输入。
- 主要结果：**含手续费、以 Gate 本所可见中间价盯市的净权益变化（USDT/有效完整日）**。每模型六日独立收益等权平均、按日与原 GLFT 配对的差；同时报告毛权益、费用、成交额、订单次数、实际撤单、持仓、最大回撤和上述 markout，避免把“少交易减亏”解释为“选择性避开毒性”。
- 固定参数之后再运行；本六日已广泛用于探索，结果只能描述探索性表现，后续需新日期或币种验证样本外稳健性。手续费情景与真实 VIP 等级、资金费率、期末真实强平/主动平仓成本、跨所采集时钟偏移是独立限制。

## 7. 阶段闸门与完成标准

1. **协议入仓**：本文件在独立实验分支可追溯，保持 `main` 不变。
2. **数据 QA 先行**：每月 1 日 4 种数据均有可复现质量报告，异常数据失败关闭；Gate 规格与历史价档/数量单位审计记录。
3. **50min 工程验证**：全部有效六日×九模型在同一 Gate 撮合、延迟、手续费设置下运行，有成对结果与过滤触发日志；测试通过才启动完整日。
4. **整日回测**：各日期持续 00:10–24:00，54 个情景均完成（异常日明确记为无效）；报告按日等权净收益与相对 β0 改善、两种模式和 β 梯度矩阵；不将 50min 结果当作“日收益”。
