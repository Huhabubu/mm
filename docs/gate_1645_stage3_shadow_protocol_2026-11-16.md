# Gate BTC 1.645σ：阶段③逐笔信号状态及理论撤单时效审计

时间：2026-11-16。六日均为2026年6—11月每月1日，10min预热、1430min交易。已探索历史，非样本外。

## 研究目标

区分原始GLFT“成交变少”和“Binance信号可能筛除逆向选择较严重的订单”。阶段①六日零手续费GLFT平均亏损49.0238USDT/日、双边β1亏损21.7754USDT/日；阶段②100ms Markout从−1.199改善到−1.081bps，仍无法建立交易减少和信号保护之间的因果分配。

## 数据回放与拒绝条件

- 固定原始官方 HBT 2.4.4 [六日回放 #43786928308](https://github.com/Huhabubu/mm/actions/runs/43786928308)以及 [阶段②完整成交后Markout #43828463022](https://github.com/Huhabubu/mm/actions/runs/43828463022)。
- 独立 HBT 重新下载同源四条原始 Tardis 流并重建目标所盘口；原始GLFT的所有下单、撤单、库存、A/k估计、官方队列模型、1ms订单请求/回复延迟、20ms同侧限制、Maker +0.02%均不变。影子信号状态只用于审计，不会传给下单函数。
- 使用相同历史Binance可见价、额外2.5ms模拟可见延迟、600s时间加权价差均值及标准差、每5s更新、1σ锚定、1.645σ门槛、Binance相对起点方向及振幅优势、首次必须由Binance主动变价激活的状态机。目标所当前中间价来自原始GLFT **HBT融合L2/trades/quotes深度**，不使用100ms事后采样报价替代。
- 新回放逐笔成交的交易所时间、观察时间、方向、价、量必须与冻结 HBT 档案严格相等；最终净权益、手续费、期末库存必须在1e−7的容差内一致。任何一日不符合，整个六日聚合失败。

## 成交前时序

对原始GLFT的第 \(i\) 笔成交，定义 \(t_i^e\) 为官方交易所成交时刻（ns），\(d_r=1\,\mathrm{ms}\) 为撤单请求向交易所送达的假设延迟，\(\varepsilon=1\,\mu\mathrm{s}\) 为同刻优先级保守余量；理论最晚请求时刻：

\[
t_i^{\mathrm{cut}}=t_i^e-d_r-\varepsilon.
\]

在该时刻前HBT真正发生过的决策上读取最后一个有效信号 \(G_i^*\)（USDT/BTC），并查询当地HBT订单状态；探针不促发下单、撤单或信号决策。定义 \(s_i=+1\) 为买成交、\(s_i=-1\) 为卖成交；互斥分类为：

- threatened：\(G_i^*>0,s_i=-1\) 或 \(G_i^*<0,s_i=+1\)，即Binance领先上涨时卖单受威胁、领先下跌时买单受威胁。
- opposite：\(G_i^*\neq0\)，但是GLFT成交方向为上述受威胁方向的另一侧。
- inactive_or_no_effect：没有有效激活价差、尚未越过全部门槛、未满足Binance主动变价激活，或已被状态机撤销有效信号的成交。

受威胁侧再标注潜在能否在最晚时刻发出有效撤单请求：本地同侧存在可撤订单、影子β1报价与当前订单价不同、距离同侧最后一次挂撤动作至少20ms、请求到达交易所时间严格早于成交。审计保留该时刻的同侧订单价格，实际订单价与后来成交价能否对齐可另外交叉核验。

## 解释边界

此状态机在 **原始GLFT的订单/回复事件与库存轨迹** 上运行，是官方回测内严格时间因果的影子诊断；与真正β1模型由于下单路径不同而产生的决策事件数可能不同。标记“理论可发撤单请求”没有真实发送请求，更没有该请求的撤单ACK或确认对应订单ID，绝不能写成“成功避免的成交”。

统计原始GLFT的受威胁、相反侧及未生效三组100/500/1000ms原生Markout和尾部分布；以独立交易日等权。与真正β1回测同刻同方向配对只能表示比较集合，订单队列和持仓路径有差异。更强的因果归因必须补上同订单ID的HBT撤单确认链、等成交强度无Binance方向对照、跨所时钟稳健性和样本外日/币种复核。日度收益均为负且尚未计入资金费率和结束时强制平仓执行成本。
