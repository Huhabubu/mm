## 10ms 网格的 as-of 对齐（复核版本）

- 每个格点仅选取该时刻之前或同一时刻最后到达的有效报价。
- 报价最多允许陈旧 2s：8,640,000 格点中 8,639,638 有效（99.9958%）；32 个格点在起始时缺少一侧，330 个格点有一侧超出新鲜度阈值。
- 有效格点的最近报价年龄样本中位数：Binance 35.210ms，OKX 76.928ms（储备样本估计）。
- 双所中间价差值 `(Binance mid / OKX mid - 1) * 10^4` 的抽样中位数约 1.296bps。此为不同永续合约的报价差异，**不能直接解释为可获利套利差价**。

### 报价新鲜度敏感性（10ms 采样网格）

同一时间点要求**两所报价均不超过指定年龄**。它表示报价状态的新鲜程度，不能当作消息网络延迟或可执行领先信号。

| 两所报价最大年龄 | 有效格点数 | 有效比例 |
|---|---:|---:|
| 20ms | 417,963 | 4.838% |
| 50ms | 1,870,353 | 21.648% |
| 100ms | 4,760,300 | 55.096% |
| 250ms | 7,356,876 | 85.149% |
| 500ms | 8,402,782 | 97.254% |
| 2s | 8,639,638 | 99.996% |

这反映了两所报价更新频率的差异和所选采样网格的交互。**20ms 同时新鲜率低，不等于有 95% 的数据丢失**；对跨所预测而言，必须允许并明确记录较旧的历史报价，或改为事件驱动特征。原先 100ms 网格出现明显相位混叠，已采用 10ms 网格复核。

## 方法边界与后续核查

1. 当前为数据完整读取、基础有效性和 **10ms 网格 QA 对齐**；尚未研究 20–50ms 的因果 Lead–Lag。
2. Tardis 不同交易所的采集基础设施位置可能不同，`local_timestamp` 是各自采集侧的到达时间，**不能无条件视为部署在同一台做市机器上的到达顺序**。后续预测必须检查交易所时钟偏差、采集点差异、时间平移及下单/撤单延迟。
3. 报价更新缺口不自动等于数据缺失；该检查还未检验 L2 逐档更新连续性、成交 ID 的完整性、跨日订单簿初始化。
4. GitHub 仓库公开，Tardis 条款限制数据再分发；因此 Actions 原始 `csv.gz` 文件仅在临时运行器下载和读取，报告保留为运行产物，本仓库不公开上传原始逐笔行情。需要长期持久保存时再采用私人存储。
