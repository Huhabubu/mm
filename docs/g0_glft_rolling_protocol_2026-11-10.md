# G0-R 与 G0-S：滚动校准事前试验方案（2026-11-10）

## 目的与论文位置

根据 hftbacktest 官方 GLFT 教程采用的每 100ms 决策、最近 10min 强度/波动率、每 5sec 更新方式，建立规范化基准：G0-S（相同估计器校准一次后固定参数）与 G0-R（相同估计器滚动校准）。本轮为 G0 工程兼容性与单时段配对交易诊断，不声称正式逐日回测或可盈利。原 `scripts/g0_glft_baseline.py` 暂留作历史缺陷实现审计，**不会**把原 174 档与新估计器直接比较为滚动增益。

## 数据、时间与执行

- Tardis OKX BTC-USDT-SWAP，2026-11-01 UTC 00:00–01:00；前 10min 禁止下单，仅产生因果训练缓冲；10–60min 在同一历史数据、相同官方 hftbacktest 2.4.4 订单簿和队列模型下分别运行静态 G0-S、滚动 G0-R，两个独立模拟器均从同一初始资金库存开始。
- 每 100ms `hbt.elapse(100_000_000)` 重放事件后读取可见中间价和已到达的主动成交，向长度 6000 的环形缓冲写入数据；滚动版在第一组 10min 数据完成时校准一次，此后每 50 个 100ms 样本即 5sec 重校准。静态版仅使用第一次计算的相同参数。**仅使用决策时刻之前已观察的数据，不涉及未来事件，不改变报价刷新频率**。
- HBT 配置维持：tick 0.1 USDT/BTC；每张合约 ctVal=0.01 BTC、lot=0.01 张、单张挂单量 0.1 张、库存绝对值最大 2 张；入单/回应各 1ms、`power_prob_queue_model(2.0)`、`no_partial_fill_exchange`，maker 2bps/taker 5bps 情景。报价由 GLFT 近似公式产生，Gamma 仍为既有情景参数 0.05。至多每侧一张尚未失效的订单，若撤单在途则等待，防止旧基准脚本可能在同侧产生多张尚未撤回订单。

## 估计定义与已知偏差处理

- 每 100ms 内按照 `max(buy_trade_price - previous_mid, previous_mid - sell_trade_price)` 取得相对于区间开始前一可见 OKX mid 的最大主动交易穿价深度，单位为真实 tick；该指标来自 hftbacktest GLFT 官方教程的无队列简化。**只使用严格穿过报价的情况**（`depth > d`），未将同价触及计为必然成交，实际挂单成交由官方 HBT 引擎处理。
- 70 个拟合阈值使用 d=0.5、1.0、1.5、…、35.0 个真实 tick，每档计算最近 600 秒有几次间隔出现穿价，除以 600 得到每秒的阈值穿价间隔强度。取 log 后线性拟合 `log λ(d)=log A−k d`，并将 `k>0`、至少 5 个正计数阈值、sigma>0、公式系数有限作为有效性门槛。
- 若某次主动成交在上一 100ms mid 基础上穿越了 >35 tick，事件计入它真正穿过的每个较近阈值，同时单独累计极端事件数作为风险诊断。与官方教程丢弃超范围事件的简化选择不同，这样保留其真实穿价作用；结果需要按极端事件处理做稳健性检验。
- 波动率 sigma 采用最近 6000 个 100ms 中间价变化的总体标准差乘 sqrt(10)，单位真实 tick/√s。环形缓冲无论样本是否活跃均只包含近 10min，先填满再首次估计。
- 后续校准失败保留上一组有效参数，但必须累积失败计数及更新轨迹；初始 10min 失败直接停止并报告。不得因亏损或成交稀少临时优化参数/报价。

## 事前验收

1. 合成测试验证真实 0.1 USDT tick 与 0.5 档阈值单位、严格穿价、大幅交易穿价、滚动窗口替换、无有效数据处理及报价形式。
2. 单个 50min 真实 OKX 数据样本中两套策略首个训练参数完全相同，HBT 模拟成交笔数与按订单状态记录的买卖成交一致，绝对库存未越过上限。
3. 真实样本 G0-R 每 5sec 重估参数并记录 (A,k,sigma)、半价差及失败次数；比较 G0-S、G0-R 的挂撤次数、实际成交、净盯市权益（USDT），并报告可见的费用与队列假设。**不因某段片段盈利就宣布有效。**
4. 仅上传聚合报告及参数轨迹；不上传 Tardis 原始行情。下一步再扩大多日独立收益与逆向选择指标。

## 未解决的经济和数学限制

- 本轮原样维持既有 Gamma=0.05 和以合约张数表示库存/订单数量；正式论文在跨合约量纲（ctVal=0.01 BTC/张、价格档为 0.1 USDT/BTC）的风险厌恶校准仍需明确。此前 GLFT 公式用 gamma 与 ORDER_QTY 的组合是已有情景做法，本轮不把其数值当成天然校准结果。
- 历史官方合约参数时点、实际账户手续费、撤单生效延迟、资金费率及队列模型仍是情景限制；只有 2026-11-01 50min 交易结果不能替代逐日收益。
