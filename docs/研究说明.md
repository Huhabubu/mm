# 研究说明：跨交易所领先信息与高频做市逆向选择缓解

## 1. 研究问题
检验 Binance 可见价格变化是否含有目标所尚未充分吸收的信息，以及是否能改善被动挂单后的不利价格变动（逆向选择，Adverse Selection）。假设：信号能识别受威胁侧；改变报价或暂停该侧能改善成交质量；改善不能完全由无方向减少成交解释；结果能够在独立日期、不同交易所和币种复现。均待正式实证，不预设盈利或严格经济因果领先。

## 2. 数据及可用范围

### 2.1 自采行情的部署、范围与时钟
本研究使用 AWS 东京区域（ap-northeast-1，物理可用区 apne1-az4，东京 1a）同机采集的 USDT 本位永续合约公共行情，原始 WebSocket（WS，持续推送数据的连接）消息归档至 Google Drive。使用公共互联网直连，不宣称交易所机房托管或专线。采集配置 v1.4 覆盖 BTC、ETH、XRP、SOL、DOGE、SUI 六种基础币，四个交易所共24个合约市场。Binance、Bybit、Bitget 合约名称如 BTCUSDT，Gate 如 BTC_USDT。每市场采集三类行情，共72个逻辑数据流（Binance 成交为聚合成交）；Binance 是信号源，其余三个市场是目标做市所。OKX 不在当前自采框架内。

采集器为每个接入端点建立 A/B 两条并行连接（双活冗余），各自校验协议状态，按因果顺序选择单一主连接，不把两连接的盘口增量拼成一个订单簿。解析前记录本地墙钟接收时间 recv_wall_ns 与单调时钟 recv_mono_ns（均以纳秒记录，时间分辨率不等于实际精度），保留交易所原始事件时间、序列号与原始消息。Chrony 时钟同步目标误差不超过1ms，每分钟采样；网络 RTT 每5分钟采样。UTC 自然日按15分钟划分96个窗口，TSV-Raw（原始消息文本）经 Zstandard 压缩、SHA-256 摘要校验后归档。合约元数据包含价格步长、数量步长及合约乘数。

## 3. 基准 GLFT 与跨所信号
GLFT（Guéant–Lehalle–Fernandez-Tapia）使用指数成交强度 λ(δ)=A exp(−kδ)。δ 是报价距离（合法价格档），A 为基准强度（每秒），k 为衰减系数（每档），σ_m 为目标所中间价波动率（档/√秒），q 为库存（张），Δ 为每单数量（张），γ 为代码风险厌恶参数（1/(张×价格档)）。当前物理一档泊松估计以100ms两侧穿透事件率校正并合并拟合对称 A、k，非分别估计；过去10分钟观察、每5秒更新。u=γΔ/k，c₁=ln(1+u)/(γΔ)，c₂=√[γ/(2AΔk)×exp((k/(γΔ)+1)ln(1+u))]；半宽 h=c₁+Δc₂σ_m/2（档），库存偏斜系数 c₂σ_m（档/张）。依据中间价、库存、半宽生成报价，执行合法价格网格和 Post-only（只能被动挂单）及库存约束。实现：glft_calibration.py、core_glft_engine.py、core_glft_rules.py。

设 m_B、m_M 为 Binance 与目标所已可见中间价（USDT/基础币），D=m_B−m_M，μ_D 为严格过去600秒的时间加权价差均值，s_D 为价差标准差（同单位），G=D−μ_D 为异常价差。每5秒更新统计。|G|≤s_D 时刷新正常锚；超出正常带锁锚。现行 1.645s_D 门槛，要求 Binance 相对锚的变动与 G 同方向且绝对变动大于目标所；首次有效激活由 Binance 中间价变化触发，同微秒目标所行情碰撞保守阻断。正常带、未达门槛或方向失效时停用。β=0 为基准，β=1 为完整异常价差修正，G>0 威胁卖侧，G<0 威胁买侧。当前引擎阈值为固定常量，配置 sigma_threshold 不应视为已验证可自由调整的开关。见 cross_exchange_signal.py 和核心引擎。

## 4. 六种模型
| 标识 | 作用 |
|---|---|
| glft | 无跨所方向修正的基准 |
| both_1p0 | 双边同向平移 |
| defensive_1p0 | 仅外移受威胁侧 |
| risk_side_pause | 撤停受威胁侧，其余侧原 GLFT |
| static_widen | 固定扩大价差，无 Binance 价格方向 |
| local_vol_pause | 本地波动率过滤，无 Binance 价格方向 |

两个控制模型参数须用独立日期训练后锁定。控制可共享 Binance 事件时钟，不宣称完全不使用其事件输入。

## 5. 回测设计
官方 hftbacktest 2.4.4，power_prob_queue_model(2.0) 队列概率模型、no_partial_fill_exchange 撮合模型。每 UTC 日独立10分钟预热、1430分钟交易，模型共享初始拟合时刻，不跨日继承库存。自采示例单笔80 USDT、库存限额20倍单笔数量、风险厌恶50/USDT（转换为代码量纲）、Binance 额外可见延迟0ms、模拟订单入站/回报各1ms、同侧冷却0ms、禁用原生改单。0ms额外延迟不等于市场无传播延迟；1ms为假设而非实测。主口径零手续费毛盯市损益（USDT）；成交额归一化 bps（1 bps=万分之一），辅助+2bps Maker收费、−0.5bps返佣情景，引擎示例 Maker+2、Taker+5bps。记录库存风险与请求数；费用情景基于冻结成交路径。期末盯市、资金费率、主动平仓成本局限需说明。

## 6. 五阶段实证流程

五阶段围绕同一研究问题逐步建立证据：首先确认损益差异的来源，再衡量成交质量，检验信号是否在成交前识别风险，排除单纯减少交易的解释，最后比较执行方式、检验单笔经济性并在独立样本验证。各阶段共用统一模型引擎、数据与日度配置；研究阶段与论文自然章节不必一一对应，阶段编号是研究论证顺序，不表示代码必须重复运行五次。

### 6.1 Stage 1：收益归因与会计核对
**目的：** 弄清原始 GLFT 与信号策略的毛损益差异从何而来，分开交易价差捕获和持仓期间的价格变化损益，避免将手续费节省误当成交易质量改善。

**怎么做：** 对每个模型使用官方 HBT（hftbacktest）成交记录和100ms权益/库存记录（Recorder），先逐笔重建现金及库存，与引擎账簿核对；再将零手续费期末盯市权益变动分解。口径 A 使用成交前最近有效采样中间价衡量价差捕获，配合区间结束库存计量价格损益；口径 B 使用成交后下一有效采样中间价，配合区间开始库存计量价格损益，仅作事后归因敏感性检查，不参与交易。两种口径均要求价差捕获加库存损益等于毛损益，代码会计残差容差为0.0001 USDT；核查手续费与净权益关系，记录无有效中间价的样本。报告毛损益、两项归因、库存均方根 RMS（反映持仓总体幅度）、成交额及会计残差。

**解决什么问题：** 策略少亏究竟来自更好的成交价格、较少承担库存价格风险，还是仅少交手续费。分解口径改变时两项贡献可以变化，总毛损益应保持一致；单独库存损益改善不能直接证明逆向选择缓解。

### 6.2 Stage 2：成交质量与尾部风险
**目的：** 检验加入信号后，实际成交的短期经济质量是否改善，特别是严重亏损成交是否减少，而非仅比较全天收益。

**怎么做：** 对每个模型的真实 HBT 模拟成交，用实际成交价与本地观察成交时刻之后100、500、1000ms的目标所原生 BBO 中间价计算总成交质量 Total Markout（方向化短期估值，单位 bps）。设 $e$ 为成交方向（买入+1、卖出−1），$p$ 为成交价（USDT/基础币），$t$ 为本地观察成交时间，$\tau$ 为未来窗口（ms），$m_M(t+\tau)$ 为该时刻最近已可见的目标所中间价，则：

$$\operatorname{TM}_{\tau}=10^4 e\frac{m_M(t+\tau)-p}{p}.$$

负值表示该笔成交相对未来中间价不利；主观察500/1000ms，100ms补充。未来报价必须在评价时点已到达且年龄不超过500ms；对未来实际更新过报价、入场报价年龄区间进行分层。分买/卖侧及全体成交报告等权均值、成交额加权均值、负值比例、10%分位数与最差10%均值，同时报告样本数及覆盖率。总 Markout 不以陈旧入场中间价代替实际成交价；另保留基于入场中间价的方向漂移用于分解。

**解决什么问题：** 判断改善是单位成交质量提升还是仅成交数量减少；均值好转但尾部恶化时须同时披露。短期估值不等于实际平仓收益，也不能证明信号的因果作用，下一阶段对此进一步检验。

### 6.3 Stage 3：成交前风险识别及可撤机会
**目的：** 检验 Binance 信号是否在基准 GLFT 成交之前就能识别受威胁侧，以及未出现在信号策略中的基准成交是否确实有较差的后续经济性。

**怎么做：** 先运行原始 GLFT，再用相同市场数据、参数和撮合引擎进行只读影子回放（shadow replay：计算信号及假想报价，不改变原策略订单）；核验基准逐笔成交和账簿一致。对于每笔基准成交，以交易所成交时间减模拟订单入站延迟、再减安全余量（当前配置1微秒）为最迟撤单请求时点，只使用截至该时点可见的信息：
- 受威胁组：信号为正且成交为卖出，或信号为负且成交为买入。
- 反向组：信号已激活但成交方向不属于受威胁侧。
- 未激活/无效组：没有有效方向信号。

检查该时点是否存在相应开放订单、能否撤单、假想报价是否改变、同侧操作间隔是否满足、订单价格与最终成交价是否一致；计算理论成交前可发撤单请求比例。按成交交易所纳秒时间和方向进行严格多重集合配对（相同键重复出现也逐个匹配），比较原 GLFT 与各信号策略的共有/基准独有成交，并结合 Stage 2 的各组 Total Markout、负值比例和尾部统计。

**解决什么问题：** 若受威胁组比未激活组更不利且信号在成交前已可用，并且信号策略缺少的基准成交集中于不利组，形成机制证据。仍须区别理论可撤、模拟路径差异与真实订单取消成功；同时间同方向配对不是实际订单 ID 或真实反事实因果匹配，不能声称每个未匹配成交都被信号成功阻止。

### 6.4 Stage 4：无 Binance 方向的成交强度对照
**目的：** 排除简单替代解释：信号模型少成交可能只是因为报价更远或高波动时停止交易，因此毛损失减少未必来自 Binance 方向信息。

**怎么做：** 在与正式评价日完全不重叠的训练日运行 GLFT、双边平移及两类无方向控制。控制 A（static_widen）在基准半宽上增加固定距离，候选为训练日基准半宽中位数的10%、25%、50%、100%；控制 B（local_vol_pause）使用目标所自身波动率阈值，候选为训练样本波动率的55%、70%、85%、95%分位数。按现有训练函数，分别选取训练期总成交笔数最接近双边平移的候选，平局按预设候选次序决定，记录候选及结果并以 SHA-256 锁文件固定参数。评价日使用冻结参数，不事后调节以强行匹配成交数量。比较各模型零手续费损益、单位成交额损益、成交质量、成交数量及库存；附含费情景。控制组可以共享 Binance 事件时钟，但不读取其价格方向来决定报价。

**解决什么问题：** 判断跨所方向信息相对“扩大价差/本地波动过滤”是否有增量价值。训练期成交强度接近不保证评价日逐日完全匹配，必须报告实际差异；若无方向控制表现相同或更好，应如实报告，不能强行归因于跨所信号。当前训练/锁定函数已存在，但完整独立训练 CLI 调度仍待验收。

### 6.5 Stage 5：信号执行方式、同笔经济性与独立验证
#### Stage 5A：执行方式比较
**目的：** 判断如何使用同一跨所信号更合适，分清双边报价调整与只保护受威胁一侧的代价及收益。

**怎么做：** 在相同数据、GLFT 初始拟合、延迟、合约数量与库存约束下比较四种核心模型：原 GLFT、双边平移、受威胁侧外移、受威胁侧撤停。报告零手续费毛盯市损益、成交额归一化损益、固定成交路径下的费率情景、各窗口 Total Markout、库存标准差/RMS/最大绝对仓位及提交、撤单和最大每秒操作请求量。按日独立评价。

**解决什么问题：** 在成交质量、库存风险、成交机会和订单操作负担之间判断不同执行方式的取舍；含费少亏可能完全来自少成交、少交费，必须结合毛损益和单位成交质量。探索样本的最佳方式不能直接当作样本外最优。

#### Stage 5B：同笔成交经济性
**目的：** 判断受威胁成交虽然后续价格漂移不利，是否同时获得更大的入场价差补偿；检验跨所信号识别风险能否转化为真实的单笔经济改善空间。

**怎么做：** 对 Stage 3 的同一基准成交集合与 Stage 2 标注按时间及方向核对一致性。在相同成交上比较入场半价差捕获、未来有向中间价漂移、两项合计、以成交价为基准的 Total Markout；按全体、受威胁、未激活、反向、理论可撤以及相对其他模型的基准独有成交分组，记录报价新鲜度、样本覆盖与费率情景。总 Markout 与旧捕获/漂移分解采用各自有效样本及分母，不能把不同样本的均值直接相加。以实际成交价基准指标为主。

**解决什么问题：** 辨别被识别的风险是否已被价差部分或全部补偿；评估回避哪些成交可能有经济意义，同时判断日常未激活成交的质量。该指标仍是短期盯市估值，不能替代组合日损益或重复计入。

#### Stage 5C：锁定执行方式与独立样本外验证
**目的：** 排除根据已观察日期挑选最优策略导致的过拟合，检验结论能否推广到未参与研究选择的行情。

**怎么做：** 只使用探索日 Stage 5A 报告，在读取留出日行情前按预定排序规则锁定一种信号执行方式。当前示例以日等权零手续费毛收益为选择指标，候选日等权库存 RMS 不得超过双边平移的1.25倍；满足库存限制者按收益排序，平局使用固定次序。记录探索日、独立留出日、候选、选择指标、库存约束、选中方式和锁文件摘要。严格分隔训练日、探索评价日与未触碰留出日，在时间向前的独立样本上使用冻结方式与 GLFT 比较，不因结果不好重新选择；历史日期检验须单独标注，不等同向前样本外。

**解决什么问题：** 观察研究结论能否脱离已探索行情、跨日期和市场复现；不能依据个别样本或逐笔数量宣称稳健显著。当前选择和校验函数已存在，独立训练/留出日调度仍需补齐和验收（统一入口主要循环 eval_dates，Stage 5C 的单日锁校验与多日留出调度也需核对）；未获授权不启动正式实验，不把函数存在当作阶段已完成。

各阶段计算以 `scripts/tokyo_l2_research_stages.py`、`scripts/fill_quality.py` 和实际锁文件、配置、报告为准。五阶段均需记录负面结果；不因假设未获支持而改变已锁定研究规范。
