# 研究说明：跨交易所领先信息与高频做市逆向选择缓解

## 1. 研究问题
检验 Binance 可见价格变化是否含有目标所尚未充分吸收的信息，以及是否能改善被动挂单后的不利价格变动（逆向选择，Adverse Selection）。假设：信号能识别受威胁侧；改变报价或暂停该侧能改善成交质量；改善不能完全由无方向减少成交解释；结果能够在独立日期、不同交易所和币种复现。均待正式实证，不预设盈利或严格经济因果领先。

## 2. 数据及可用范围
使用东京自采 USDT 永续行情的 Google Drive 分区归档，每 UTC 自然日96个15分钟窗口。同一采集环境的本地接收时间（纳秒）决定信息可见性；保留交易所原始事件时间，不能把二者差值直接解释成实测单程网络延迟。

| 交易所 | 角色 | 策略所用频道 |
|---|---|---|
| Binance Futures | 信号 | bookTicker（最优买卖报价） |
| Gate Futures | 做市 | futures.book_ticker、futures.obu、futures.trades |
| Bybit Linear | 做市 | orderbook.1、orderbook.50、publicTrade |
| Bitget v3 | 做市 | books1、books50、publicTrade |

BBO（Best Bid and Offer）为最优买卖价；L2 为多档深度；trades 为逐笔成交。币种通过配置选择，合约元数据给出合法价格、数量步长及合约乘数；支持适配不代表所有币种都有合格数据或完整实测。OKX 不在当前自采适配范围。可用日期、币种及缺失情况以外部质检分支当次报告为准，不编造静态可用清单。

下载校验索引、manifest 与原始数据 SHA-256；绑定外部日度与协议质检规则摘要、archive revision；流式转换为 hftbacktest 事件数组。全部模型复用同一转换结果，缓存验证输入摘要、合约规格与转换代码。批量同日可共享 Binance BBO 提取。生产采集及完整质检系统由其他分支负责，本分支仅读取质检证据和验证回测输入。已知缺口或未验证连续性只能作为诊断，严格质检未通过不得用于正式结论。

## 3. 基准 GLFT 与跨所信号
GLFT（Guéant–Lehalle–Fernandez-Tapia）使用指数成交强度 λ(δ)=A exp(−kδ)。δ 是报价距离（合法价格档），A 为基准强度（每秒），k 为衰减系数（每档），σ_m 为目标所中间价波动率（档/√秒），q 为库存（张），Δ 为每单数量（张），γ 为代码风险厌恶参数（1/(张×价格档)）。当前物理一档泊松估计以100ms两侧穿透事件率校正并合并拟合对称 A、k，非分别估计；过去10分钟观察、每5秒更新。u=γΔ/k，c₁=ln(1+u)/(γΔ)，c₂=√[γ/(2AΔk)×exp((k/(γΔ)+1)ln(1+u))]；半宽 h=c₁+Δc₂σ_m/2（档），库存偏斜系数 c₂σ_m（档/张）。依据中间价、库存、半宽生成报价，执行合法价格网格和 Post-only（只能被动挂单）及库存约束。实现：glft_calibration.py、core_glft_engine.py、core_glft_rules.py。

设 m_B、m_M 为 Binance 与目标所已可见中间价（USDT/基础币），D=m_B−m_M，μ_D 为严格过去600秒的时间加权价差均值，s_D 为价差标准差（同单位），G=D−μ_D 为异常价差。每5秒更新统计。|G|≤s_D 时刷新正常锚；超出正常带锁锚。现行 1.645s_D 门槛，要求 Binance 相对锚的变动与 G 同方向且绝对变动大于目标所；首次有效激活由 Binance 中间价变化触发，同微秒目标所行情碰撞保守阻断。正常带、未达门槛或方向失效时停用。β=0 为基准，β=1 为完整异常价差修正，G>0 威胁卖侧，G<0 威胁买侧。当前引擎阈值为固定常量，配置 sigma_threshold 不应视为已验证可自由调整的开关。见 cross_exchange_signal.py 和核心引擎。

## 4. 六种模型
| 标识 | 作用 |
|---|---|
| glft | 无跨所方向修正的基准 |
| both_1p0 | 双边同向平移 |
| defensive_1p0 | 仅外移受威胁侧 |
| risk_side_pause | 撤停受威胁侧，其余侧原 GLFT |
| static_widen | 固定扩大价差，无 Binance 价格方向 |
| local_vol_pause | 本地波动率过滤，无 Binance 价格方向 |

两个控制模型参数须用独立日期训练后锁定。控制可共享 Binance 事件时钟，不宣称完全不使用其事件输入。

## 5. 回测设计
官方 hftbacktest 2.4.4，power_prob_queue_model(2.0) 队列概率模型、no_partial_fill_exchange 撮合模型。每 UTC 日独立10分钟预热、1430分钟交易，模型共享初始拟合时刻，不跨日继承库存。自采示例单笔80 USDT、库存限额20倍单笔数量、风险厌恶50/USDT（转换为代码量纲）、Binance 额外可见延迟0ms、模拟订单入站/回报各1ms、同侧冷却0ms、禁用原生改单。0ms额外延迟不等于市场无传播延迟；1ms为假设而非实测。主口径零手续费毛盯市损益（USDT）；成交额归一化 bps（1 bps=万分之一），辅助+2bps Maker收费、−0.5bps返佣情景，引擎示例 Maker+2、Taker+5bps。记录库存风险与请求数；费用情景基于冻结成交路径。期末盯市、资金费率、主动平仓成本局限需说明。

## 6. 五阶段实证流程
| 阶段 | 研究问题及方法 | 输出 |
|---|---|---|
| 1 收益归因 | 两套会计分解，核对价差捕获、库存损益闭合至零手续费权益变化 | 毛损益、库存、残差 |
| 2 成交质量 | 实际成交价至未来100/500/1000ms中间价的方向化收益，检查报价新鲜度 | Total Markout、分侧、尾部、负值比例 |
| 3 机制验证 | 基准 GLFT 只读影子信号；核验逐笔成交与账簿一致，分受威胁、未激活/无效、反向，核算理论可撤和成交配对 | 各组风险、理论可撤比例、基准独有成交（不等同因果阻止） |
| 4 排除替代解释 | 独立训练日锁定固定扩宽和本地波动率阈值，评价日与方向策略对照 | 成交强度、质量、收益 |
| 5A 执行消融 | 四核心模型共享数据与约束，比较双边、单边、暂停 | 损益、成交质量、库存、请求 |
| 5B 同笔经济性 | 同一基准成交集合分解价差捕获与后续漂移，检查 Stage2/3 一致性 | Total Markout、capture、drift、费用情景 |
| 5C 独立验证 | 先按探索日收益与库存规则锁定模式，再用未触碰日期验证 | 锁文件、样本外结果 |

e 为成交方向（买+1、卖−1），p 为成交价（USDT/基础币），t 为本地观察成交时间，τ 为未来窗口（ms）；Total Markout=10000×e×(m_M(t+τ)−p)/p（bps）。与中间价到中间价的方向漂移区分，具体新鲜度及分层以 fill_quality.py 为准。Stage4/5C 需独立日期、锁文件和授权；框架包含锁定、校验函数，统一入口读取锁文件，训练与独立运行流程仍待验收，不能声称已完成实证。
