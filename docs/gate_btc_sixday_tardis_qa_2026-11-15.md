## 事前检查与重要区别

1. 验证每份数据首条在 UTC 零点后 5 秒内、末条覆盖整日最后 30 秒；文件必需字段齐全，无采集本地时间倒序、非法价格、非有限数量或负接收延迟。
2. 检查 Gate L2 初始两侧快照和增量/重置的元信息；约 3,400 万行主要来自盘口多价格档更新，并不等于 3,400 万个独立行情时刻。不能将所有 `is_snapshot=true` 视作“整日只有初始快照”，也不能用某个固定秒数的静默判断成交一定丢失。
3. 对 L2、quotes、Binance 最优报价记录大于 10/30/60s 的异常采集静默；若某流有大于 30s 的未解释空窗即拒绝当前日期。**逐笔成交 trades 的 30s 静默可能是市场没有成交，因此仅记录间隔，不因静默本身判定消息丢失**。
4. Gate trades.amount 经逐行检查按整数张数解释，与当前 API 的合约面值 `quanto_multiplier` 和最小交易张数配对；每份数据的价格档也按照 Gate `order_price_round` 审计。历史合约规格变更仍需独立确认。
5. 利用开头 30s Gate 原始三类数据测试官方 `hftbacktest==2.4.4` 的 `convert_fuse`，包括 `snapshot_mode=process`、事件顺序校验和真实最优盘口回放：[兼容性工作流](https://github.com/Huhabubu/mm/actions/runs/43730935874) 成功。
6. 此次 QA 属于必要但非充分的数据完整性证据：目前未获得可与 Tardis 原始报价逐 ID 对照的全交易所官方完整成交明细，亦未对 6 日所有 L2 更新逐条执行独立的第二套盘口重建一致性校验。因此严谨表述为“**在既定字段、时间、快照及长间隔检查下，未发现阻止实验的明显缺失；未证明逐条绝对无丢包**”。

## 阶段结论

六个历史日期 **6/6 满足当前预设的整日 QA 闸门**，可进入下一阶段 50min 官方 HBT 运行。合约费率来自 Gate 公共合约 API 在本次运行时的观察值，不代表各历史日期全部账户 VIP 级别。策略结果必须含手续费，整日运行前必须先通过 50min 模型工程验证。
