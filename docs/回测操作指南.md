# 回测操作指南

本地完整 Git 克隆、Python 3.12+、Git 和 Kaggle CLI；python -m pip install -r requirements.txt。使用本地已有 Kaggle Token 与已有私有 Notebook、只读 Drive 凭据私有 Dataset。两类凭据不得入库。Kaggle 安装 HBT 2.4.4、zstandard 0.23.0、rclone v1.68.2。无需 GitHub Actions。

先 git fetch origin。数据公共接口固定依赖 collector/python 与 collector/specs（78f7a69ac070cdb1d823e93a871b0801c4a1e3b7），由本地 Git 历史临时导出，不迁入生产系统。质检快照读取 origin/tokyo-l2-qa-state，规则摘要读取 origin/main；记录两者提交。当前采集配置与质检报告必须匹配。

configs/ 内5份是已有配置示例，11月23日为已探索日。单组改 kaggle/job.json args 为 ["--config","configs/你的配置.json"]；批量为 ["--batch-config","configs/你的批量配置.json"]，同日同信号交易所可共享 Binance 行情。先提交配置，job.files 包含所有所需 scripts、配置和锁文件。不要加入密钥、原始行情、逐笔成交。Stage4/5C 独立训练、锁定、运行仍需验收。默认诊断允许已知缺口；正式实证须关闭 diagnostic_allow_known_gaps、核对日度和协议质检，不能用容忍缺口替代放行。

仅准备（不提交）：
```bash
python kaggle/local_submit.py --notebook owner/notebook --cred-dataset owner/private-credentials --nb-dir ../paper-kaggle-build
```
确认配置、QA 快照及隐私后，使用新空目录并显式加 --submit，或手动 kaggle kernels push -p ../paper-kaggle-build。查看和取回报告：
```bash
kaggle kernels status owner/notebook
kaggle kernels output owner/notebook -p ../paper-results
```
会更新指定已有 Notebook，勿共用正在运行的任务。检查 job_manifest.json、job_status.json、数据质检及结果后再筛选安全汇总。当前本地调度入口尚未真实调用 Kaggle 验收。
