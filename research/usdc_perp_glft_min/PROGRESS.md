- 延迟：本地 − 交易所时间 p50 约 2.1–2.5ms，最小 1.2–1.4ms，无负值。这是 Tardis 采集机的位置，不代表我们的 EC2。多行组的到达跨度 p95 为 0.73ms，"首次越过阈值"比"等整组到齐"最多早不到 1ms。

## 第五版：墙前一档挂单研究，策略不变

提交 `4b2bca1`（`wall_study.py`）、`6df7739`（单测）、`535a0d1`（打包）、`a7e1b50`（`kaggle_task.py` 接入）、`04493b5`（workflow），对应 [Actions 45826621109](https://github.com/Huhabubu/mm/actions/runs/45826621109)。`job_status.git_sha` = `04493b5` 已核对，returncode 0。9 个模型 PnL 与前几版逐位一致。

**做法**：用 ETHUSDC 的 `incremental_book_L2`（1887 万行）和逐笔成交（51 万行）重建盘口，放 1 手虚拟单（0.03 ETH，无库存限制、无冲击）。
- 队列：排在可见挂量之后，该价位的成交消耗队列，挂量减少时队列同步截断；成交价穿过挂单价即成交。
- 时序：下单、撤单、改价都在决策后 1ms 生效，生效前旧单仍可成交。
- “墙”：距中间价 50 tick 以内、挂量超过分位数阈值的最近一档。阈值取各档挂量的 q90 / q95 / q99，分别为 14.4 / 20.9 / 74.0 ETH，对应各档挂量中位数 1.6 ETH。
- 虚拟单挂在墙前一档：买单挂墙价 +1 tick，卖单挂墙价 −1 tick。
- 撤单规则：
  - 一直挂着，直到价格离开 60 tick；
  - 墙被清空就撤；
  - 墙剩不到初始的 30% 或 50% 就撤。
- “击穿”：成交后 5s 内最优价越过墙价。
- 对照组：在中间价固定距离 d 处挂单，中间价一变就改价。

| 方案 | 成交 | 击穿率 | markout 100ms / 1s / 60s (bp) | 未击穿 1s | 击穿 1s |
|---|---|---|---|---|---|
| 墙 q90，一直挂 | 10697 | 94.0% | −0.75 / −0.84 / −0.58 | +0.55（640 笔） | −0.93 |
| 墙 q95，一直挂 | 7714 | 93.2% | −0.78 / −0.88 / −0.71 | +0.52（522 笔） | −0.98 |
| 墙 q99，一直挂 | 3466 | 93.6% | −0.73 / −0.85 / −0.54 | +0.55（223 笔） | −0.94 |
| 墙 q95，剩 50% 撤 | 4295 | 89.5% | −1.02 / −1.15 / −0.82 | +0.54（450 笔） | −1.35 |
| 墙 q99，剩 50% 撤 | 1393 | 88.9% | −1.13 / −1.18 / −0.52 | +0.53（155 笔） | −1.39 |
| 固定 d=1 | 40205 | — | −0.75 / −0.86 / −0.84 | — | — |
| 固定 d=12 | 11009 | — | −0.95 / −1.01 / −0.59 | — | — |
| 固定 d=32 | 2201 | — | −1.41 / −1.42 / −0.07 | — | — |

- **墙基本扛不住**：在墙前一档成交后，5s 内墙被击穿的比例是 89–94%，只有 6–11% 扛住。扛住时 1s markout 约 +0.55bp，击穿时 −0.9 到 −1.4bp。按 $p_{hold}R-(1-p_{hold})L$ 计算，结果明显为负。
- **原因是选择偏差**：墙前一档能成交，基本说明卖压已经打到墙上；单纯摸到墙前、然后回头的单很少。
- **按“墙变薄就撤”撤单没用**：撤单后 5s 内确实有 24–54% 被击穿，说明撤对了一部分；但剩下的成交更毒（1s 约 −1.15bp），因为来不及撤的正是那些 1ms 内被扫穿的单。
- **墙大小没有区分度**：q90、q95、q99 三档结果几乎一样。
- **固定距离对照**：挂得越宽，短期 markout 越差，−0.75bp 到 −1.41bp。60s markout 随距离改善，d=32 为 −0.07bp，说明大幅波动后有部分回补，但仍未转正。
- 结论（单日，未做显著性检验）：在 ETHUSDC 上，“墙前一档等反弹”和“单纯挂宽”都没有正 edge，不值得做成策略。

**限制**：
- L2 重建出的中间价全天只变化 40,707 次，bookTicker 有 163,659 次，可见 L2 更新有合并或滞后。墙的判断和 markout 都基于这个更粗的盘口，可能偏向“墙已在被吃时才看到”。这一点未核实 Tardis 该流的推送频率。
- 虚拟单的队列模型与 hftbacktest 的 `power_prob(2.0)` 不同，所以固定距离对照的数值不能直接和基准 GLFT 比，比如 d=12 是 −0.95bp，基准是 −0.47bp。
- 虚拟单没有库存约束，PnL 只是 markout 的加总，不是策略盈亏。

## 第四版：纯事件研究，策略不变

提交 `f44d21f`（`event_study.py`）、`e57e3ea`（单测）、`c5326fc`（打包）、`5bcf636`（workflow）、`ab0805f`（`kaggle_task.py` 接入），对应 [Actions 45801943135](https://github.com/Huhabubu/mm/actions/runs/45801943135)。`job_status.git_sha` = `ab0805f` 已核对，returncode 0，耗时 976s。9 个模型 PnL 与第二、三版逐位一致（基准 −25.69155，defensive β=1 −25.19175）。

### Lead-lag：USDT 是否领先 USDC

对一侧每次中间价变化，统计另一侧在事件前后窗口内的带符号变化（tick，相对事件方向），括号内为同向比例 p_same。

| 时钟 | 方向 | 事件数 | 同一时间戳 | 前 1 / 5 / 50ms | 后 1 / 5 / 50ms |
|---|---|---|---|---|---|
| 交易所 | USDT 变 → 看 USDC | 53,565 | 1.09 tick, 27.1% | 0.93 / 3.63 / 11.12 tick（24.1% / 45.8% / 65.7%） | 0.98 / 2.96 / 6.44 tick（27.6% / 48.8% / 61.2%） |
| 交易所 | USDC 变 → 看 USDT | 108,212 | 0.57 tick, 13.4% | 0.64 / 2.28 / 4.89 tick（13.7% / 27.7% / 36.2%） | 0.45 / 1.62 / 4.83 tick（11.9% / 25.0% / 36.7%） |
| 本地 | USDT 变 → 看 USDC | 81,829 | 0（分开采集） | 1.19 / 4.11 / 11.83 tick（28.1% / 50.8% / 68.9%） | 1.23 / 3.76 / 7.67 tick（30.8% / 54.6% / 65.2%） |
| 本地 | USDC 变 → 看 USDT | 163,659 | 0 | 0.73 / 2.66 / 5.17 tick（15.6% / 31.7% / 39.5%） | 0.59 / 2.01 / 5.80 tick（14.7% / 29.0% / 40.7%） |

交易所时钟下 USDT 事件数（53,565）少于本地时钟（81,829），推测是交易所时间戳更粗，同一时间戳合并了更多更新（未核实）。

- 两个方向都是“事件前已动的量 ≥ 事件后继续动的量”，更像对共同冲击的同步反应，不是干净的单向领先。
- 不对称：一次 USDT 中间价变化之后 5ms 内，USDC 同向再动的概率约 49–55%，平均约 3–3.8 tick（1 tick≈0.044bp）；反方向只有 25–29%。USDT 跳动更稀、每次信息量更大，≤5ms 内存在可利用的延续，但幅度很小。
- 判断：没有证据支持“USDT 在时间上领先 USDC”；证据支持的是“USDT 的一次跳动对接下来几 ms 的 USDC 方向有一定预测力”。

### 基准成交按成交前的变化分桶

6625 笔基准成交，每笔名义约 67.9 USDC（1bp≈0.00679 USDC）。adverse 表示成交前窗口内的变化方向对我们不利（买单成交前价格下跌等），比较 100ms markout。全天 100ms 口径亏损合计约 21.2 USDC。

| 序列 | 窗口 | adverse 笔数 / m100 | none 笔数 / m100 | adverse 桶 100ms 亏损 | 相对 none 的超额亏损 |
|---|---|---|---|---|---|
| `signal_actionable`（本地时钟，扣除 1ms 延迟后可见的 USDT） | 1ms | 309 / −0.83bp | 6255 / −0.45bp | 1.75 USDC | 0.80 USDC |
| 同上 | 5ms | 504 / −0.78bp | 5972 / −0.45bp | 2.66 USDC | 1.13 USDC |
| 同上 | 10ms | 569 / −0.76bp | 5827 / −0.45bp | 2.92 USDC | 1.20 USDC |
| `signal_exch`（交易所时钟，零延迟理想情形） | 5ms | 1426 / −0.73bp | 5105 / −0.41bp | 7.09 USDC | 3.14 USDC |
| `target_exch`（USDC 自身） | 1ms | 3512 / −0.47bp | 3046 / −0.48bp | — | 无区分度 |
| `signal_actionable_when_target_flat`（USDC 未动时的 USDT） | 1ms | 110 / −1.02bp | 2900 / −0.46bp | 0.76 USDC | 0.42 USDC |
| 同上 | 5ms | 46 / −1.23bp | 2400 / −0.45bp | 0.38 USDC | 0.24 USDC |

- **USDT 有预测力**：可操作口径下，成交前 USDT 逆向跳动的成交 markout 约为其余成交的 1.7 倍。USDC 未动时，USDT 逆向跳动的成交更毒（−1.0 到 −1.2bp，60s 为 −2.4 到 −3.8bp），但只有几十到一百多笔。
- **能挽回的上限很小**：按 USDT 跳动撤掉受威胁一侧，即使挡掉全部 adverse 桶且不影响其他成交，上限约 1.7–2.9 USDC；只算超额部分约 0.8–1.2 USDC。零延迟理想情形也只有 3–7 USDC。全天亏损为 25.7 USDC。
- **USDC 自身的变化没有区分度**：53% 的成交在成交前 1ms 内 USDC 已逆向变化，这是成交本身的特征（价格穿过挂单），不是可利用的信号。
- **主体问题不变**：none 桶（成交前 USDT 没动）约 6000 笔，markout 仍有 −0.45bp，占 100ms 亏损的约 85–90%。这部分亏损与 USDT 信号无关，来自基准 GLFT 本身的报价位置或成交模型。

### 结论与限制

- 已确认：USDT 跳动对随后 1–5ms 的 USDC 有方向预测力，但两边主要是同步变化；按这个信号撤单的收益上限约 1–3 USDC/天，不足以扭亏。
- 限制：单日（2026-11-01，周日），未做显著性和多日稳定性检验；交易所时钟与本地时钟会影响 lead-lag 结论；回测成交由 USDC 自身成交数据触发，队列位置是模型假设；markout 均值受尾部影响。
